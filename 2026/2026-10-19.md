### Grok Bot 一周升级：电脑任务快 3 倍、能读 X Chat；博主分享自动编程、SEO 托管和电话订座玩法
*作者：Elon Musk（@elonmusk）· 10/18 10:14、10:18、10/19 01:10；小墨同学（@xiaomovps）· 10/18 10:13、17:19；Viking（@vikingmute）· 10/18 21:40（北京时间）*

马斯克转发的升级清单（来自用户 @melvindvivas 的总结）：电脑任务速度快 3 倍、回复时间不到原来一半、语音通话更快且记忆更好、可以读取你的 X Chat 私信、在 X 上 @bot 就能让它办事、邮件自动化更聪明，并新增了一批连接器；马斯克还说团队每天对 Grok Bot 做大约 20 项改进。几位用户分享了实际玩法：
- **电话订座**：Brian Roemmele 做了一个只负责打电话订餐厅的 Grok Bot，说一句"今晚 7 点左右订 4 人"，它会自己找餐厅电话、问清可接受的时间和预订名字，复述确认后才拨号，结束后转述餐厅原话并可加进日历；拨号要给 Bot 接一个电话服务（他用的是 ClawCall 免费档，30 通或 30 分钟），并设了不交信用卡、不随意留言等限制。
- **手机上布置编程任务**（小墨）：需要 X 订阅、GitHub 账号、Cursor 账号和 Grok Bot；把任务发给 Grok Bot，它拆解后交给 Cursor 的云端 agent 写代码、在云电脑上实测，完成后发截图和录屏验收，最后由 GitHub CI 检查和自动部署，"只需要发一个 PR"。
- **替代 GPT 的尝试**（小墨）：他下个月打算退订 GPT，剩下生图和 Computer Use 两块：Grok 的生图做简单封面够用，但人像细节不如 GPT；电脑操作则靠在 Bot 自带的服务器上装浏览器和第三方 MCP / skill 来补，流畅度还比不上。
- **SEO 全托管**（Viking）：给 Grok Bot 接了第三方 Google Search Console MCP，设定每周定时观察数据、定计划、改网站上线，只在上线后通知他。

### 两条值得抄的 Agent 规则：5000 token 文件上限、"你是同事不是奴仆"
*作者：Matt Pocock（@mattpocockuk）· 10/18 14:38；onevcat（@onevcat）· 10/18 09:25（北京时间）*

Matt Pocock 的"今日提示词"：让 agent 写一个 pre-commit 钩子，禁止提交超过 5000 token 的文件（按"字节数 ÷ 4"估算 token），只检查暂存区文件，跳过 lockfile、代码生成文件这类不是 agent 写的东西，并在报错信息里写清楚该怎么拆文件；他称这是给代码库做过最简单也最值的投资，还补充说确定性的规则就该用确定性的方式强制执行。onevcat 则在全局 `AGENTS.md` 里加了两条：① 用户可能出错，遇到明显错误或决策冲突要毫不留情地指出，"你是同事，不是奴仆"；② 多个相互依赖的 PR 用 `gh stack` 管理（他说模型们目前还不太爱用它）。

### Pi 生态三则：核心包怎么选、Pi Durable 出了原生苹果版、上下文压缩插件
*作者：小墨同学（@xiaomovps）· 10/18 14:00、19:16、22:59（北京时间）*

- **核心包**：Pi 背后是一整套拆开的库——`pi-ai`（统一接 OpenAI、Anthropic、Google 等，自带鉴权与 token / 费用统计，会话中途可换模型）、`pi-agent-core`（有状态的 agent 运行时，管工具调用和事件流）、`pi-tui`（差分渲染的终端 UI 库，不闪屏）、`pi-durable`（对话、工具调用和状态先落盘，进程挂了重开接着干，仍是实验性）、`pi-mcp`（独立 MCP 客户端，支持 stdio 和 Streamable HTTP）。只想写代码装 `pi-coding-agent` 就够，除 pi-durable 外都已打包在内。
- **Apple Bots**：MacStories 的 Federico Viticci 把 Pi Durable 大部分移植成 Swift，做成原生苹果 App：接入 20 多个 Apple 框架（能放歌、调 Shazam）、后台语音可选 GPT-Live 或 Grok Voice、有子 agent、记忆和 WebKit 浏览器操作，App 被杀掉也能从断点继续；目前尚未开源。Pi 作者 Mario 预告下周在 Cloudflare Durable Objects 和 Vercel 上正式支持休眠，并加入遥测。
- **上下文压缩插件**（适合 128K / 256K 小上下文的本地模型）：`pi-compaction-control` 设上下文硬上限（默认 256K）提前触发压缩；`pi-compaction-model` 用 `/compaction-model` 换更便宜的模型做总结；`pi-session-compaction` 用到 60% 时在合适时机主动压缩；`pi-compaction-recall` 让模型在总结丢了名字和数字时回头搜原文。小墨的建议是插件只能缓解，根本办法还是换上下文更大的模型。

### tsc-ts 与 scriptc 是什么关系：TypeScript 编译器绕了一圈回到 TypeScript
*作者：lencx（@lencx_）· 10/18 08:51（北京时间）*

前一天日报提过 Vercel Labs 的 tsc-ts，lencx 把两个项目讲清楚了：`scriptc` 把 TypeScript / JavaScript 编译成原生可执行文件或 WebAssembly，程序可脱离 Node.js 运行；`tsc-ts` 用这套能力把 TypeScript 编译器本身做成原生程序，照常做类型检查、生成 JS 和类型声明。对比：传统 tsc 用 TS 写、以 JS 运行；tsgo 用 Go 写、以原生程序运行；tsc-ts 用 TS 写、也以原生程序运行，官方称比 tsgo 快 2–4 倍。
