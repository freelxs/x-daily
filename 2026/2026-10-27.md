### magpie 10-26 网关故障尸检报告：全局锁卡住所有请求，v0.1.1566 已修复
*作者：yetone（@yetone）· 10/26 14:22、15:25 北京时间；Xuanwo（@xuanwo）· 10/26 23:59 北京时间；kevinzhow（@kevinzhow）· 10/26 16:33 北京时间*

10 月 25 日到 26 日下午，不少人更新 magpie 后网关"挂了"：Codex 等 Agent 请求一直转圈，2 分钟后报 504。yetone 发了详细的尸检报告和道歉：根因是本地脱敏模型 pf-serve 的加载和识别都在一把全局锁里做同步 I/O，影响打开"用本地模型查找"的用户，换新版 pf-serve 后的冷启动和新加的 504 看门狗又把问题放大。v0.1.1566 起加载和识别不再持锁，识别结果（只存哈希、位置和类别）落盘、重启不用重读，等模型时会直接说明在等它；还卡的话可以运行 `magpie goroutines` 把输出发给他。他反省的几点包括测试只用了假 pf-serve、一天发了二十多个版本。Xuanwo 另外反馈 magpie 没给 Codex 请求附上正确的 max_output_tokens，导致发往 DeepSeek 的请求被默认输出上限卡住；kevinzhow 看完后感慨，用 Agent 做产品时，设计测试应该和开发同等重要。

*作者：yetone（@yetone）· 10/26 15:44 北京时间*

yetone 认为很多人觉得 Agent 不顺手，是因为没用 `--dangerously-skip-permissions` 参数启动 Claude Code。他说这个参数不只决定要不要人工批准，还会改变给模型的提示词，不加时 Claude 的主动性会明显下降。他的前提是把 Agent 放在一台没有敏感信息的单独机器上放手让它干，介意安全的人不必照搬。

### JetBrains 开源 agentic IDE ThinkRail，内核是 Pi
*作者：Viking（@vikingmute）· 10/26 09:39 北京时间*

ThinkRail 是 JetBrains InnovationHub 出品的开源 IDE，把 Pi 编程 Agent 包进一个带 Monaco 编辑器、终端和 diff 的轻量界面。它的核心是 Workspaces：每个工作区是一个独立的 git worktree，有自己的分支、文件、终端和对话；项目意图记录在一份 Agent 会读取的 SPEC 文件里。Viking 说 ThinkRail 只是个轻壳，不会偷偷塞提示词，真正干活的还是 Pi，用 Pi 的人可以试试。支持 macOS、Windows 和 Linux。

### Tailscale SSH 被曝漏洞：一台设备失守可拿到其他服务器 root 权限
*作者：小墨同学（@xiaomovps）· 10/26 08:57 北京时间；小众软件（@appinn）· 10/26 10:42 北京时间*

安全研究员 Erica Windisch 发布名为 Tailworm 的报告，在 Tailscale v1.104.2 和 headscale v0.29.5 中发现 11 项问题、分 5 组。最严重的是 Tailscale SSH：已获准使用它的用户可通过 Unix 套接字转发，借以 root 运行的 tailscaled 拿到目标主机 root 权限，实验室里每台设备不到 1 秒被攻陷并能自动扩散；其他问题涉及 Serve、App Connector、DERP 中继客户端和 headscale。截至发稿还没有 CVE 或修复版本。小墨建议收紧 SSH ACL；不需要转发的设置 `TS_SSH_DISABLE_FORWARDING=1` 并重启服务，完全不用内置 SSH 的可执行 `tailscale set --ssh=false`（先确保有其他登录方式）；并检查 Serve/Funnel 是否暴露了 Docker Socket 等高权限接口。他也提醒，经 Tailscale 内网连普通 OpenSSH 和用 Tailscale 内置 SSH 是两回事。
