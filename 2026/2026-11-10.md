### Claude Fable 5.2 / Mythos 5.2 发布：比 Opus 5.5 强一档，API 降价两成
*作者：宝玉（@dotey）；ZEN（@supezen） · 11/10 03:09、11/10 07:52 北京时间*

宝玉整理：Anthropic 11 月 9 日发布 Claude Fable 5.2 和 Mythos 5.2，官方称在测过的几乎所有能力上都比 Opus 5.5 强一档，输出速度比 5.1 最多快 30%，API 价格从每百万输入/输出 Token 10/50 美元降到 8/40 美元（模型名 `claude-fable-5-2`，AWS、Google Cloud、Azure 均已上线；可选快速模式最多快 2.5 倍，价格翻倍为 16/80 美元）。订阅方面：Max（100 美元/月）、Ultra（200 美元/月）和 Team 高级席位用法不变，每周最多拿一半额度用于 Fable，另送 1–3 次“Fable 额度重置”（2027 年 3 月 8 日前用完）；Pro（20 美元/月）和 Team 标准席位平时用 Fable 需开“额外用量”按量付费，但 11 月 9–16 日这一周临时从套餐额度里扣、不另收费，17 日起恢复；免费用户用不了。Claude Code 需升级到 2.1.321 或更高版本。

两者是同一个模型，区别只在护栏：Fable 带网络安全和生物方面的护栏，对所有付费用户开放；Mythos 无此限制，只给通过审核的机构。评测方面（均为 Anthropic 自己发布的数字，第三方尚未复现）：FrontierCode 2.0 上 Fable 5.2 开 Xhigh 档 49.1%，High 档 45.3%，与 Opus 5.5 最高档的 45.5% 持平但每任务花费约一半；演示案例包括 1000 个 agent 用 30 小时把费马大定理证明改写成 Lean 代码。ZEN 当天已用上 Fable 5.2 并发了使用截图。

### Meta 发布最小模型 Muse Ember：单价与 Claude Haiku 5.5 相同，跑同一套测试只花约三分之一的钱
*作者：宝玉（@dotey） · 11/10 03:04 北京时间*

Muse Ember 是 Meta 迄今最小最便宜的模型，面向 agent 的重复杂活（调工具、编程小任务、请求分派、长文档信息提取）。开发者今天即可通过 Meta Model API（模型名 `muse-ember-1.0`）或 Muse Code 使用；价格每百万 Token 输入 0.1 美元、输出 0.5 美元，缓存命中输入 0.004 美元，上下文 100 万 Token，单次最多输出 51.2 万 Token，支持文字、图片、音频、视频；不开放权重。

据 Artificial Analysis：综合智能指数 Muse Ember 36 分（Muse Spark 1.3 为 37 分），平均每题花 0.14 美元对 2.39 美元，即 Meta 所说“便宜 17 倍”；Claude Haiku 5.5 同为 36 分但每题 0.41 美元。Terminal-Bench 4.0 上 Muse Ember 40.9%（Haiku 32.8%）；但 FrontierCode 2.0 上 27.2%，落后 Haiku 的 34.9%；知识问答只答对 21.1%（Haiku 34.7%），原因是 64% 的题选择不答，幻觉率 17.4%。Meta 建议难题交给 Muse Wonder 做规划，大量执行交给 Muse Ember。

### 让 AI 写代码的方法论：少约束、说“为什么”、重验证、设计要加约束
*作者：Matt Pocock（@mattpocockuk）；Nico投资有道（@tychozzz）；Viking（@vikingmute）；宝玉（@dotey） · 11/09 19:06、11/10 04:22、11/09 21:30、11/09 14:16、11/09 21:14、11/10 04:45 北京时间*

- Matt Pocock：为“Software Factory”这个词辩护——承认它有点吹，也是在蹭热度，但指向的确是真实变化；另一条技巧：让 agent 来“拷问”你需求时，要讲“为什么”（问题）而不是“做什么”（方案），例如写“管理员目前看不到应用里重要数据的总览”，而不是“给管理员做个带图表和筛选的分析面板”，这样 agent 才有空间更有创造性。
- Nico投资有道：今年下半年（他说是 GPT5.6 上线后）取消了此前按产品/UI/前后端/测试分角色 Agent 的全部工作流和 coding skill，直接对着 Codex 或 Claude 提需求，“大方向人把关，小决策和执行细节全交给 AI”，认为过多限制反而束缚模型。
- vikingmute：转述一篇文章的最佳实践——给 AI 明确的验证机制，不要相信 agent 自己说做完了，要它提供新的 E2E 用例通过流程、截图甚至录屏；另一条说，做设计仍是应用最大护城河，没有强约束时，即使 Opus 5.5 写出的页面也字多、配色杂、一眼 AI。
- 宝玉：每次新模型发布是清理精简提示词的好时机，转引了一条提示词：“阅读整个项目，找出所有损坏、不一致、低效或不再需要的东西。修复你确信的部分，并将其余部分列出供我审查。”
