### Karpathy 周末作品 HackerTube：用 HN 20 年评论筛出 6,454 个值得看的 YouTube 视频
*作者：Andrej Karpathy（@karpathy）· 11/02 02:14 北京时间*

Karpathy 嫌 YouTube 推荐太差，让 Claude 把 Hacker News 20 年间约 4300 万条评论过滤一遍，挑出被反复推荐的 6,454 个视频，做成网站 HackerTube，前后约 2 小时（Claude Code 桌面版 + Opus 5.5，Medium 推理强度）。特点：不用登录就有推荐（状态只存在本地浏览器）；缩略图取视频中段的代表帧，而不是经过 A/B 测试优化的「标题党」封面；评论分析的底层数据打包成一个 zip 提供下载，可以交给自己的 AI 做个人版本；还有「HackerTube Longs」长视频板块。他说自己只做了三件手工活：在 Google Cloud 后台建 YouTube API Key、开一台 VPS、买域名，其余加固、部署、优化都由 Claude 完成。

### DeepSeek Harness 发布 Super-agent 架构设计并开源研究原型
*作者：小墨同学（@xiaomovps）· 11/01 16:16 北京时间；Vonng（@RonVonng）· 11/02 07:22；Pass（@passluo）· 11/01 23:29；钟星宇（@zhongxingyuyes）· 11/01 22:03*

DeepSeek Harness 团队发长文《探索 Super-agent 设计》（文章声明这是架构思路，不是现有功能介绍），目标是让 Agent 长期在线、主动接活、能并发、能自恢复。核心设计：两层架构，长期存在的 Router 只负责与人交互和派活（甚至可以不给 Bash 工具，用轻量模型即可），每个任务交给上下文隔离的 Worker，各有自己的 Session 和工作目录；Ticket 机制让任务脱离单个 Session，PR 收到修改意见能接着原任务处理；事件驱动，原型可监听 GitHub 和飞书，先按授权和规则判断再建任务，还可开「观察模式」只记录不执行；Worker 中断后保留状态、重试恢复；只在需要人决定或交付结果时打扰人。文中实测：Super-agent 任务完成时间 p50/p95 为 12.4/15.7 分钟，单 Session + 子 Agent 工具（中性提示词）为 20.4/29.5 分钟。小墨同学觉得它和 Pi Durable 思路相近；Vonng 写了点评《为什么小秘书遇上大工程就拉胯》；Pass 说这和 yetone 的 AI 开发工作法很像（并澄清不是说抄袭）；钟星宇说 kun 里已实现类似的 router-worker 架构。

### Pi 用自研 pi-schema 替换 TypeBox：部分场景快 100 倍，内存降到约 1/8
*作者：小墨同学（@xiaomovps）· 11/01 22:15 北京时间*

Pi 作者 Mario（@badlogicgames）宣布 TypeBox 不再是 Pi 部分核心包的依赖，改用自研的 pi-schema。它不用 eval 就能做 JSON Schema 校验，在禁止动态代码生成的环境里部分测试比 TypeBox 快 100 倍以上；3200 个 Schema 的内存从 54.7MB 降到 7.1MB（压缩后 8.5KB）。工具参数校验更宽容，比如模型把数字 10 写成字符串 "10" 会自动转换；支持 JSON Schema Draft 7 和 2020-12，核心测试 2223 项过了 2222 项。普通插件不用重写（保留 TypeBox 兼容入口），但直接从 pi-ai 导入 Type、Static 的自研 Agent 后续要调整。改动目前还在开发分支。

### Tw93 的 GitHub Actions 提速提示词（10 条，可直接交给 Agent）；Mole 推出 Pro 功能 Beta
*作者：Tw93（@HiTw93）· 11/01 15:42、21:48 北京时间*

AI 让写代码变快，但 CI 校验还是慢。Tw93 优化了 Mole、Kaku、Pake 的 CI，并公开提示词要点：用 `gh` 拉最近 50 次运行，把每个 job 拆成排队、准备、测试三段找规律；同一 PR 连推只跑最新一次（`cancel-in-progress`，main 除外）；只改文档不触发 CI（`paths` 过滤，注意必需检查被跳过会卡住 PR）；优先用 setup 类 action 自带缓存，Rust 用 `Swatinem/rust-cache`，每仓库缓存上限 10GB；工具下载预编译版，不要现场 `go install` / `cargo install`；无依赖的 job 并行；免费账号 macOS 最多同时 5 个，lint、格式化等移到 Ubuntu；最后给出优化前后对比。同日 Mole（Mac / PC 清理工具）推出 Pro 功能：查看哪个应用在吃带宽、测速、悬停查看 Wi-Fi / 磁盘 / 电池细节，在「设置 → 接收 Beta 更新」里开启。

### 几则观点：AI 没让工程师涨薪、Personal Agent 的对手是「什么都不做」、Redux 该回归？
*作者：Barret李靖（@Barret_China）· 11/02 00:40、00:47；Matt Pocock（@mattpocockuk）· 11/02 04:18、11/01 16:13；Viking（@vikingmute）· 11/01 22:15 北京时间*

Barret 认为 AI 主要在替代人工解决「已知问题」：工程师交付量翻倍，公司不需要那么多需求时反而可能少招人，收入增长要靠增量价值（比如独立做产品卖给市场）；他还说用户不想要「AI 管家」，想要的是少生病、事情自动办好，一个每月省半小时却要花一小时配置的助理没有经济价值，Personal Agent 最大的对手可能是用户什么都不做。Matt Pocock 提出 Redux 式「状态只放一处」的框架可能对 Agent 有利（缩小决策空间），但状态终究分散在 URL 和服务端，需要配套的 Effect 系统；他也在重做 Sandcastle v1，定位「帮你搭软件工厂」，内置 6 种 harness（Claude Code、Codex 等）并对接主流沙箱服务。Viking 转述一个观点：给自己解决痛点的独立开发时代过去了，别人能很快 vibe coding 出替代品，应去为有钱、有痛点、不写代码的人解决问题。

宝玉推荐 TobyAtLarge 的长文。要点：软著（自 2017 年免官费，常规 1–3 个月）、App 备案（2023 年 9 月起必需，走云平台备案，免费，实测多为一周左右）、五家商店开发者账号（免费，荣耀 / OPPO / vivo / 小米实名互认）都是等待成本；真正磨人的是每次发版要在小米、应用宝、OPPO、vivo、荣耀五个后台各传一遍。五家都有上架 API（小米 RSA 分块签名、应用宝 HMAC-SHA256 且每天 50 次更新调用、OPPO token 48 小时、vivo 毫秒时间戳 HMAC、荣耀五步提交链），作者团队把流程做成 Agent Skill：`status` 只读查状态 → `plan` 体检 APK（签名、版本、SHA-256 等）→ 人工确认 → `submit` 五家提审并同步自建下载站。他们 20 个月发了 48 个版本。

### 老人眉毛变长不是「长寿眉」
*作者：Dr.Wang（@HotmailfromSH）· 11/01 13:24 北京时间*

眉毛变长与寿命无关，是正常衰老现象，原因有二：毛囊退化信号变迟钝，生长期延长，眉毛能一直长；年龄增长后毛囊对雄激素的反应改变，雄激素抑制头皮毛囊（导致脱发），却促进眉毛、耳毛、鼻毛变长变粗。
